# Common v0.13.0

Minor release over v0.12.0, published through the immutable `v0.13.0` tag and
`release-tag.yml` using npm trusted publishing and provenance.

## Changes

- #60 — Add shared QueueDock and queue lifecycle projection: accepted but
  unprocessed user messages remain queued, cancellation removes the intended
  message, and consumed steering stays in the coherent turn.
- Preserve requires_action as an awaiting turn, retain pending tools, and derive
  elapsed time from the turn's actual timestamps.
- Align managed event/state mapping with the official CMA wire contract; keep
  OMA queue extensions separate from official SDK event types.
- Restore composer text on settle-only send rejection; never display a rejected
  prompt as queued. Retained queue rows do not offer edit/remove actions.
- Hold fallback ACP input while a permission request is open instead of racing
  or cancelling that request; send it after permission settlement.
- Make external Cursor Cloud live verification advisory, with failed steps,
  logs and an explicit warning preserved. Unit/type/build/release checks remain
  blocking.

## Validation and limitations

The feature PR passed CI verify and release-check. Local verification passed
913 tests, typecheck, build, dist freshness, coverage, browser bundle validation,
and the 45k-event performance check. Cursor Cloud live is not certified: its
API returned usage_limit_exceeded. Downstream apps must run their own tests.

Consumers should use `@openma/common@^0.13.0` after publication, or the immutable
Git reference `github:openma-ai/openma-common#v0.13.0` where appropriate. OMA must
remove its development tarball and update its lockfile/Dockerfile separately.
