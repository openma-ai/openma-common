# Common v0.13.0 (proposed — not tagged or published)

## Managed session events: queued user messages

Aligns the Managed conversation projection with the official Claude Managed
Agents `processed_at` semantics.

- New `projectConversation()` / `projectCanonicalChat()` return
  `{ turns, queued }`. `queued` lists `user.message` events that were accepted
  but not processed yet (`QueuedUserMessage`, `reason: "pending" | "deferred"`).
- A `user.message` with `processed_at: null` no longer starts a new turn, so a
  message sent mid-turn cannot split the running turn. When the same event id
  is re-emitted with a timestamp, it starts its own turn in order; the
  timestamped copy wins over the queued echo.
- Fallback for servers that still stamp `processed_at` at accept time: a
  timestamped `user.message` that arrives while the current turn has not reached
  idle/terminated is treated as queued (`reason: "deferred"`) until that turn
  ends (FIFO). Opt out with `{ deferMidTurnUserMessages: false }` (e.g. for
  hosts whose mid-turn steering injects messages into the running turn).
- `projectConversationTurns()` / `projectCanonicalChatTurns()` keep their
  return types and now exclude queued messages from `turns`.

Minor bump: new exports and a visible projection behavior change.
