# Common v0.7.2

Released through the immutable Git tag `v0.7.2`. The package remains private to
npm by design; Git installs use committed `dist/` and need no build lifecycle.

## Changes

Patch over `v0.7.1` (`5d839b5`). No exports were removed or renamed.

- #10 (`077db8f`) centralizes inclusive ACP message fork in
  `@openma/common/acp-runtime`. The contract text is
  [docs/fork-support.md](../fork-support.md). `dist/` for these exports was
  updated in that commit.

### New APIs

`forkSupport()` is the only client entry for whole-session and inclusive
message fork. It accepts an `AcpSession` or an initialize response
(`agentCapabilities` and `agentInfo`). Clients stop hardcoding harness names
and versions.

| `level` | `reason` | When |
|---|---|---|
| `none` | `not-initialized` | Input is null or has no `agentCapabilities`. |
| `none` | `session-fork-not-advertised` | No `sessionCapabilities.fork`, even if the capability key is present. |
| `session` | `message-fork-not-advertised` | Session fork is advertised, and the capability key is absent. |
| `session` | `message-fork-capability-invalid` | The key exists, but `version` is not `1` or `inclusive` is not `true`. |
| `message` | `message-fork-advertised` | The capability key is valid. `messageFork.source` is `"capability"`. |
| `message` | `message-fork-verified-adapter` | No key, and `agentInfo` matches the internal verified-adapter table. `messageFork.source` is `"verified-adapter"`. |

`message` is English and can be shown to a user. `messageFork` is present
only when `level` is `"message"`, as `{ version: 1, inclusive: true, source }`.

The verified-adapter table is not exported. It covers upstream adapters that
implement inclusive fork but do not emit the capability key:
`codex-acp` / `@agentclientprotocol/codex-acp` at or above `1.10.0`, and
`claude-acp` / `@agentclientprotocol/claude-agent-acp` at or above `0.75.1`.
Comparison is strict `x.y.z`. Own adapters (dsh-acp, pi-acp) advertise the
capability key instead of relying on this table.

Also exported:

- `ACP_INCLUSIVE_FORK_VERSION` (`1`), `ACP_INCLUSIVE_FORK_CAPABILITY`
  (`Object.freeze({ version: 1, inclusive: true })`), and
  `acpInclusiveForkCapabilityMeta()`, which returns
  `{ jetbrains: { air: { fork: ACP_INCLUSIVE_FORK_CAPABILITY } } }` to
  deep-merge into `agentCapabilities._meta`.
- `acpForkPointsFromMessages()` numbers already-merged top-level assistant
  messages. Callers collapse `<id>:segment:<n>` chunks into `<id>` and
  concatenate that message's text first. `messageOccurrence` is the 1-based
  count of identical text in the time-ordered prefix, including the message
  itself.
- `acpForkRequestMeta()` is unchanged. It still builds `jetbrains.air.fork`
  v1. The fingerprint is `sha256:` plus the SHA-256 of the message text's
  UTF-8 bytes.
- `AcpSession.forkSupport` is `forkSupport(session)`. `supportsSessionFork`
  is unchanged.

### `forkPoint`

`SessionOptions.forkPoint` is valid only together with
`forkFromAcpSessionId`. Using it alone throws
`forkPoint can only be used together with forkFromAcpSessionId` before
`session/fork`.

After `initialize` and before `session/fork`, the runtime calls
`forkSupport()` on the initialize result. If the caller set `forkPoint`, or
placed `jetbrains.air.fork` on `sessionRequestMeta`, and the level is not
`"message"`, start throws
`ACP agent does not support message-level fork (${reason}): ${message}` and
does not send `session/fork`. It does not fall back to a whole-session fork.

A supported `forkPoint` is deep-merged into `sessionRequestMeta` for that
`session/fork` request only. Nested objects merge key by key, and the fork
meta wins on a leaf conflict, so other keys such as `claudeCode` stay in
place. A whole-session fork that sets neither `forkPoint` nor
`jetbrains.air.fork` is unchanged.

### Capability contract

Agents that implement inclusive message fork advertise both of these on
`initialize`:

```json
"agentCapabilities": {
  "sessionCapabilities": { "fork": {} },
  "_meta": { "jetbrains": { "air": { "fork": { "version": 1, "inclusive": true } } } }
}
```

The path is the nested object `agentCapabilities._meta.jetbrains.air.fork`,
the same path as the request-side `_meta`. A flat `"jetbrains.air.fork"` key
is not the capability. `version` and `inclusive: true` are both required.
`version` is the request extension version. `inclusive: true` means
truncation includes the target message. Message fork is an extension of
`session/fork`, so `sessionCapabilities.fork: {}` must be present too.
Existing `_meta` keys (for example `dsh.cordis` or `pi`) are deep-merged and
not overwritten.

Truncation keeps source history through the target assistant message,
inclusive, and drops everything after it. Tool calls on that message whose
results sit after it are removed from the truncated message. Tool calls that
already completed before that message stay. The new session remains a legal
model transcript, and `session/load` replay ends on the target message.
Adapter parse rules, including the refusal to silently fall back to a
whole-session fork, are in `docs/fork-support.md` sections B, C, and D.

### Downstream migration (backchat, clash)

This commit does not change consumer manifests. After the immutable tag
`v0.7.2` exists, backchat and clash install it and delete their own harness
name and version checks:

```json
"@openma/common": "github:openma-ai/openma-common#v0.7.2"
```

Call `forkSupport()` on the initialize response or the live session. When
`level` is not `"message"`, show `support.message` and do not send
`jetbrains.air.fork`. Build points with `acpForkPointsFromMessages()` from
time-ordered, already-merged top-level assistant messages, then start with
`forkFromAcpSessionId` and `forkPoint`. Clash's `supportsAcpMessageFork`
moves into the internal verified-adapter table here; clients do not keep a
copy.

dsh-acp and pi-acp copy `ACP_INCLUSIVE_FORK_CAPABILITY` byte-identical and
advertise it from `initialize`. They do not depend on this private package,
and they can land in parallel with the tag. Clients do not wait on those
adapters before calling `forkSupport()` against agents that already advertise
the key or match the verified-adapter table.

### Release checks

A pull request that changes `package.json` `version` runs
`scripts/release-check.mjs` as the `release-check` CI job. The job fails
unless all of the following hold:

- `docs/releases/vX.Y.Z.md` exists, and every pull request merged to the base
  branch since the previous `v*` tag is mentioned there as `#N`. Numbers come
  from `(#N)` in the commit subject. A longer number does not satisfy a
  shorter one. Each missing number is printed on its own line.
- `docs/releases/` contains no `unreleased-*.md` file.
- The README Git install pin is `github:openma-ai/openma-common#vX.Y.Z`.
- `pnpm build` leaves `dist/` with no diff.
- The bump is patch only. A minor bump also needs the pull request label
  `release:minor`. A major bump needs `release:major`.

Every pull request, including one that does not change the version, prints a
`::notice::` for each pull request merged to the base since the previous tag.
A commit in that range with no `(#N)` is listed the same way. Those notices
do not fail the job.

Pushing a `v*` tag runs `.github/workflows/release-tag.yml`. The tag name must
be `v` plus `package.json` `version`, `docs/releases/vX.Y.Z.md` must exist,
and `pnpm build` must leave `dist/` clean.

This release commit bumps `package.json`, the Git install pin in `README.md`,
and these notes, and adds the release checks above. It does not publish to
npm, move an existing tag, or create a GitHub release.

Consumer manifests and remote branches were not changed. This package release
does not certify or publish any consumer application's installer.
